Summary

AI Usage Panel runs locally on your Windows computer. It has no publisher-operated server, product account, analytics, advertising or automatic crash reporting. The publisher does not automatically receive your settings, profiles, credentials, usage figures, device identifiers or diagnostics.

Data leaves the app only when you deliberately use a provider tool or API, or when you choose to send a support message. Those operations are described below.

In the portable edition from v177, the relative runtime/data, runtime/icons, runtime/logs and runtime/wipe locations in this table are under %LOCALAPPDATA%\AI Usage Panel. The bundled Python stays beside the executable in its own runtime/python. On first launch, the app may copy the old writable runtime into this stable location without deleting the original. When it finds managed profiles but no saved settings in a separate extraction, it starts with new settings without asking to import another folder. An automatic in-place import can include a legacy Claude Code usage configuration folder; its credential contents are not inspected.

In the Microsoft Store MSIX edition, settings, generated icons, logs and other writable runtime data are stored in the app's per-user package LocalState directory under %LOCALAPPDATA%\Packages\<package-family-name>\LocalState. On a first Store install without saved LocalState data, it can import portable v177 state. Store updates retain their existing LocalState. In both editions, managed provider profiles default to %LOCALAPPDATA%\AI Usage Panel\Profiles; Settings → Profiles Folder can move that complete tree to another absolute local path. Installed program files remain in the read-only WindowsApps package.

The app also creates Start Menu/Desktop shortcuts and per-user Windows registry entries for application identity, taskbar grouping and notifications. These entries contain product/profile identity and icon paths, not provider passwords or session tokens.

Provider credentials and local sign-out

Apart from the opaque one-time import described above, AI Usage Panel does not copy, export, decrypt, display or transmit credentials stored by Claude Desktop, ChatGPT, Claude Code or Codex. For usage monitoring it starts the official Claude Code or Codex CLI under a dedicated configuration folder; the official tool owns its authentication and network connection.

The app may test whether an expected credential file exists, without opening its contents, to decide whether a usage login is available.

When you explicitly choose to sign out of a managed profile, the app closes that profile and removes its local authentication. To perform that requested action, it edits the managed Chromium cookie databases only to delete cookies for the relevant provider domains, removes authentication fields from that managed profile's local configuration, and deletes its Local Storage, Session Storage, IndexedDB and Service Worker folders. It does not read or transmit cookie values. This may delete unsaved local-only drafts or other local site state. It does not delete cloud conversation history, revoke sessions on other devices or touch an unmanaged/default provider profile.

For Claude, this sign-out also runs the official Claude Code sign-out command under the selected profile's dedicated configuration, then removes that profile's local Claude Code usage folder, including its local settings and caches. If that profile had been using your global Claude Code sign-in instead, the app does not log out or delete that global sign-in. An app-owned marker in the selected managed profile prevents it from borrowing the global sign-in again, even after the app is updated in a new folder. Explicitly starting a new Claude usage sign-in for this profile removes the marker after the official CLI verifies the new session. Other managed profiles are not changed.

Each managed ChatGPT profile starts the ChatGPT application with a configuration folder of its own (codex, inside that profile's folder), where the application keeps that profile's sign-in; the Codex CLI reads that profile's usage through the same folder. Once, the first time version 156 opens a ChatGPT profile last opened by an earlier version, the app closes that profile's window and deletes the provider cookies and the Local Storage, Session Storage, IndexedDB and Service Worker folders of that window's data, as it does for a sign-out, because that data may belong to the account of another profile. The profile's own codex folder is kept. Your own ChatGPT and Codex configuration outside the managed profiles is never opened, changed or deleted.

Network activity

AI Usage Panel itself makes an outbound HTTPS request only when you provide your own API key and request validation. That is a read-only GET to https://api.anthropic.com/v1/models or https://api.openai.com/v1/models, with certificate verification and redirects refused. The key is sent only to the provider whose key you supplied.

Separately, when you enable usage monitoring or a usage sign-in, the app starts the official Claude Code or Codex CLI installed on your computer. That tool may open the provider's sign-in page and connect to its vendor under your account. AI Usage Panel reads the account label and quota/rate-limit values the CLI prints. Provider terms apply, and the feature is not intended to bypass any usage limit.

Opening a managed Claude or ChatGPT window also starts the provider application you installed. Its own privacy policy and terms govern its processing.

Support messages

Support Request and Feedback save their form fields locally when you click Send or close the form; the values reappear until AI Usage Panel Reset. Support keeps selected attachment paths, not copies. The selected files are checked again before an e-mail draft is opened. The app has no mail credentials and sends nothing by itself.

Without files, Windows opens the default MAILTO e-mail app. With files, the app can add each original file separately when classic Outlook is the Windows MAILTO default and its local composition interface is available. Otherwise it reports that automatic attachments are unavailable and leaves the form saved. You review the completed draft and decide whether to send it.

Messages you send to suporte.aiusage@hotmail.com may contain your e-mail address, message and attachments. Do not include passwords, authentication codes, API keys or cookies. Messages are used to answer and troubleshoot your request, are not sold, and are retained only as reasonably necessary for support, legal or security purposes. You may request access, correction or deletion at that address, subject to records the publisher must retain by law.

Your controls

  • Provider mode controls whether the app starts a usage CLI, opens dedicated provider windows, or does both.
  • Notification and refresh settings control local monitoring behaviour.
  • Profile sign-out removes the selected managed profile's local session data after a confirmation warning or, for the Claude sign-in guide, after Cancel or X. For Claude it also ends the isolated usage session and stops borrowing any global Claude Code login for that profile.
  • Settings → AI Usage Panel Reset removes app-managed profiles, saved Feedback and Support Request forms, earlier unsent feedback and local runtime data; it also attempts to remove related shortcuts and application identity entries.
  • Deleting a portable app folder removes its program files, but the stable LocalAppData runtime, shortcuts, registry entries and managed profiles may require the in-app Reset or manual removal. Store uninstall normally removes its LocalState; external profiles may remain.

Security

API keys are stored using Windows DPAPI for the current Windows account. Legacy plaintext keys are migrated only after protection succeeds for every value. If protection or protected storage fails, the existing file is preserved and an unprotected key is not used for validation. A pre-existing plaintext file is not erased by that error path. Provider CLI sign-ins and manual usage use separate paths. Already-protected files are not rewritten on normal reads.

TLS certificate verification is required for direct API-key checks. Local diagnostic redaction and path-bound deletion checks reduce accidental disclosure or deletion. No local application can guarantee protection if the Windows account or computer itself is compromised. DPAPI does not protect against every program running as the same user or an administrator on a compromised device.
